## 2026-05-13 — Phase 7: LLM-классификация ТН ВЭД по справочнику ЕЭС

**Что**: Гибридная классификация — rule-based код показывается мгновенно, LLM
(GPT-4o-mini) через 700 мс уточняет по официальной curated reference из главы 61-63
справочника ЕЭС.

**Новые файлы:**
- `src/lib/tnved-llm.ts` — OpenAI fetch-клиент + curated reference (130 строк)
- `src/app/api/tnved-suggest/route.ts` — POST endpoint с LLM-первым / rule-based fallback
- `docs/raw/ett-ch61.pdf`, `ett-ch62.pdf`, `ett-ch63.pdf` — официальные ПДФ из ЕЭС
  (https://eec.eaeunion.org/comission/department/catr/ett/) — для админа как справочник

**Что в форме:**
- При вводе товара (название + состав + тип + пол) → rule-based код мгновенно в поле
- Через 700 мс debounce → fetch /api/tnved-suggest → если LLM согласен, оставляет; если уточнил — перезаписывает
- Бэйдж возле поля: 🟡 «проверяется по справочнику ЕАЭС…» / 🟢 «подобран по справочнику ЕАЭС»
- Override клиента сохраняется (если он руками поправил код — LLM больше не вмешивается)

**Env:**
- `OPENAI_API_KEY` — добавлен в `.env.example`. Без ключа система продолжает работать на rule-based.
- Стоимость: ~$0.0002 за один вызов (GPT-4o-mini)

**Архитектура promptа:**
- System: «Ты — эксперт по ТН ВЭД ЕАЭС, специализирующийся на одежде»
- User: входные данные + curated reference (глава 61: трикотаж, 62: швейные, 63: прочие) + правило HS Note 2(A) о доминанте >50% + известные EAEU исключения + маппинги моделей (лонгслив → фуфайка и т.п.)
- Response format: `{"code":"XXXXXXXXXX","rationale":"..."}` (JSON-mode, temperature 0)
- Timeout: 15 сек, после — фалбэк

**Тесты:**
- TypeScript clean: 0 ошибок
- Все смок-тесты по-прежнему зелёные (39/39 словарь, 11/11 ТН ВЭД rule-based)
- LLM-классификатор не тестируется автоматически (требует API ключа); пользователь подтверждает работу через форму

**Что НЕ сделано (известное):**
- Полный парсинг PDF в структурированный JSON — попытка через pdftotext+regex и pdfplumber дала загрязнённые данные из-за многоколоночного layout. Curated reference в коде покрывает нужное для одежды
- Семантический поиск по EAEU базе для админа — отдельная задача (вариант (б)/(в) из сценариев)
- Rate limiting на /api/tnved-suggest — публичный endpoint без аутентификации, при росте трафика добавить
- Кэширование одинаковых запросов — каждый вызов уникален для текущего MVP

## 2026-05-11 — Phase 5: фундаментальная переработка композера по официальной памятке

**Что**: Композер `compose.ts` полностью переписан под официальную методику
(`docs/памятка_методика_формулировок.docx`).

**Главные изменения:**

1. **Иерархия натуральных волокон в названии ткани** (лён → шерсть → хлопок → шёлк):
   - Лён в составе ≥30% → ткань называется по льну (полульняная/чистольняная), даже если хлопок доминирует
   - Шерсть ≥70% (без других натуральных) → шерстяная; ≥30% или mix-других → полушерстяная
   - Хлопок ≥50% → хлопчатобумажная
   - Шёлк ≥50% → «из нитей натурального шёлка»

2. **Носитель привязан к производству**:
   - Трикотажные → «пряжа»
   - Швейные → «ткань»

3. **Связка волокон**:
   - Трикотаж: «в смеси» / «из смеси»
   - Швейные: «в сочетании» / «из сочетания»

4. **Порог «вложение vs смесь»** (по памятке): ≤10% компонента → «с вложением»,
   >10% → «в смеси/сочетании»

5. **Особое правило для шерсти ≥70%**:
   - 1 не-шерстяная категория примеси → упоминаем «в сочетании с …»
   - 2+ не-шерстяных категорий → просто «из шерстяной ткани» (без перечисления)

6. **Состав в скобках с %** после каждой фразы материалов: `(80% полиэстер, 15% вискоза, 5% эластан)`, по убыванию.

7. **Суффикс «волокон и нитей»**:
   - 2 категории → каждая со своим суффиксом («синтетических нитей и хлопковых волокон»)
   - 3+ категорий → общий суффикс («искусственных, синтетических и хлопковых волокон и нитей»)

8. **Слой 1/2/3** определяется автоматически:
   - Бельевые 1-го слоя — фуфайки, футболки, майки, лонгсливы, трусы, пижамы, ноч. сорочки, боди и т.п.
   - Верхние 2-го слоя — платья, блузки, юбки, брюки, костюмы и т.п.
   - Верхние 3-го слоя — пальто, куртки, плащи, шубы
   - + опциональный per-item флаг `lining_over_40` → 3-й слой

9. **Возрастные группы для детей**: «для детей старше трёх лет (ясельной, дошкольной, школьной возрастных групп) и подростков».
   Смешанные возрасты → «для взрослых и детей».
   Мужчины+женщины → «для взрослых».

10. **Канонические названия по ГОСТ 17037-2022** (словарь из ~50 паттернов):
   - Лонгслив → «фуфайки с длинным рукавом, модель «лонгслив»»
   - Футболка → «фуфайки (футболки)»
   - Свитшот → «джемперы, в том числе модель «свитшот»»
   - Худи → «толстовки, в том числе модель «худи»»
   - Бриджи/бермуды/капри/джинсы/карго → «брюки, в том числе модель «N»»
   - Боксеры/слипы/стринги/бразилианы → «трусы, в том числе модель «N»»
   - И т.д.

11. **Перечень изделий — внутри основного описания** (а не отдельным абзацем):
   `…для женщин, в комплектах и отдельными предметами: платья, блузки, костюмы, с маркировкой «Фарида мода»`
