# Rule: формат деклараций соответствия (ТР ТС 017/2011)

Источник: [`docs/памятка_методика_формулировок.docx`](../../docs/памятка_методика_формулировок.docx)
(официальная памятка заказчика) + [`docs/composition-dictionary.docx`](../../docs/composition-dictionary.docx)
(33 правки пользователя в словарь составов).

Базовые ГОСТы для лёгкой промышленности (используются как нормативный источник):
ГОСТ 17037-2022 (термины швейных/трикотажных изделий), ГОСТ 13784-94 (волокна и нити),
ГОСТ 28000-2004 (шерстяные ткани), ГОСТ 15968-2014 (льняные одежные), ГОСТ 10138-93
(льняные бельевые), ГОСТ 4.419-86 (пряжа льняная), ГОСТ 25294-2003 (платьево-блузочный
ассортимент), ГОСТ 25295-2003 (пальтово-костюмный ассортимент).

## 1. Структура описания группы продукции

```
Изделия {слой} {производство} {fabric_phrase}[, {fabric_phrase_2}]…
{gender_phrase}: {assortment_list}, с маркировкой «{brand}»
```

Реализовано в `src/templates/declaration-eaeu-light/compose.ts → composeDeclaration()`.

## 2. Слойность (1/2/3)

Определяется через `detectItemLayer` по словарю + опциональный per-item флаг `lining_over_40`.

- **1-й слой («бельевые первого слоя»)** — трусы, фуфайки, футболки, майки, лонгсливы,
  пижамы, боди, комбинации, панталоны, кальсоны, бюстгальтеры (корсетные),
  сорочки/халаты ночные, пеньюары, купальники
- **2-й слой («верхние второго слоя»)** — платья, блузки, юбки, сарафаны, рубашки,
  брюки, костюмы, пиджаки, жакеты, жилеты, толстовки, свитеры, кардиганы, джемперы
- **3-й слой («верхние третьего слоя»)** — пальто, куртки, плащи, шубы, дублёнки,
  пуховики, парки. Также любое 2-уровневое изделие с подкладкой >40% (`lining_over_40: true`)

## 3. Носитель и связка волокон

- Швейные (`woven`) → носитель **«ткань»**, связка **«в сочетании / из сочетания»**
- Трикотажные (`knit`) → носитель **«пряжа»**, связка **«в смеси / из смеси»**

Реализовано: `carrierGen()`, `connectorVSmesi()`, `connectorIzSmesi()`.

## 4. Названия тканей по доминирующему натуральному волокну

Иерархия приоритета (НЕ простая «самый высокий %»):

| Условие | Название |
|---|---|
| Лён 100% | чистольняная ткань / пряжа |
| Лён ≥30% | полульняная (даже если хлопок доминирует) |
| Шерсть 100% | чистошерстяная |
| Шерсть 70-99% + 1 не-шерсть категория | шерстяная (+ «в сочетании с …» или «с вложением …») |
| Шерсть 70-99% + 2+ не-шерстяных категорий | шерстяная (БЕЗ упоминания примеси) |
| Шерсть 30-69% | полушерстяная (без упоминания примеси) |
| Хлопок 100% | хлопчатобумажная |
| Хлопок строго >50% | хлопчатобумажная + примесь («с вложением» ≤10% / «в сочетании» >10%) |
| Шёлк 100% | из {ткани/пряжи} из нитей натурального шёлка |
| Шёлк строго >50% | из нитей натурального шёлка + примесь |
| Только синтетика/искусственные / прочее | из {carrier} из {категория} либо из сочетания {категорий} |

**Важно — пороги хлопка/шёлка СТРОГО >50%**: при ровно 50/50 нет доминанты, фалбэк на «сочетание». Лён и шерсть имеют «полу-» формы, поэтому работают при ≥30%/≥30%.

## 5. «Вложение» vs «смесь/сочетание»

Из памятки P12: компонент **≤10%** → «с вложением», **>10%** → «в смеси / в сочетании».

## 6. Суффикс «волокон и нитей»

- 1 категория синтетика → «синтетических нитей»
- 1 категория искусственная/натуральная → «{adj} волокон»
- 2 категории — каждая со своим хвостом: «синтетических нитей и хлопковых волокон»
- 3+ категории — единый суффикс: «искусственных, синтетических и хлопковых волокон и нитей»

## 7. Гендер

Per-item dropdown в форме: `auto / women / men / kids / adults`.

Агрегация (`aggregateGenderPhrase`):
- Все товары одного гендера → «для женщин» / «для мужчин» / «для детей» / «для взрослых»
- «Для детей» использует расширенную фразу: «для детей старше трёх лет (ясельной, дошкольной, школьной возрастных групп) и подростков»
- Mix мужчины+женщины → «для взрослых»
- Mix взрослые + дети → «для взрослых и детей»
- Если ничего не определилось → дефолт «для взрослых»

## 8. Перечень изделий по ГОСТ 17037-2022

Словарь в `compose.ts → ITEM_DICTIONARY` (~50 паттернов). Структура: `{ base, model? }`.

### Терминология ГОСТ 17037 (модели в кавычках)

| Разговорное | Канонично |
|---|---|
| Лонгслив | фуфайки с длинным рукавом, модель «лонгслив» |
| Футболка | фуфайки (футболки) |
| **Сарафан** | **платья, в том числе модель «сарафан»** |
| Топ | майки, в том числе модель «топ» |
| Свитшот | джемперы, в том числе модель «свитшот» |
| Худи | толстовки, в том числе модель «худи» |
| Бриджи / бермуды / капри / джинсы / карго | брюки, в том числе модель «N» |
| Боксеры / слипы / стринги / бразилианы / танго / макси | трусы, в том числе модель «N» |
| Водолазка | свитеры, модель «водолазка» |
| Пеньюар | халаты ночные, в том числе модель «пеньюар» |
| Комбидресс | боди, в том числе модель «комбидресс» |
| Рубашка | сорочки верхние (рубашки) |

### Слойные правила

- Халат **домашний** → 2-й слой
- Халат **ночной** (пеньюар) → 1-й слой (бельевые)
- Бюстгальтеры → **корсетные** (отдельная СС). Комплект «трусы+бюстгальтер» → 2 декларации
- У детей до 3 лет (ГОСТ для новорождённых/ясельных) можно «кофточка(-и)»

### КРИТИЧНО — что НЕЛЬЗЯ писать

- ❌ «Кофта» — разговорное, в ГОСТах не существует
- ❌ Самостоятельные «бриджи», «бермуды», «свитшоты», «лонгсливы», «худи» — это модели, не наименования

### Агрегация моделей в ассортименте

`formatAssortment`:
- 1 модель: «{base}, в том числе модель «X»»
- 2+ моделей: «{base}, в том числе моделей: «X», «Y», «Z»»
- База + модели автоматически схлопываются: платья + сарафан → «платья, в том числе модель «сарафан»» (не дублируется «платья»)

## 9. Динамические ГОСТы

В `compose.ts → gostReferencesBlock`. Использует **базовое имя** из словаря, не raw input.

| Категория | ГОСТ |
|---|---|
| Бельевые (1-й слой, корсетные) | (нет — отдельный ГОСТ не подключён) |
| Платья, блузки, юбки, сарафаны, рубашки женские | **ГОСТ 25294-2003** |
| **Костюмы, пиджаки, жакеты, жилеты** + Пальто, куртки, плащи, шубы, дублёнки | **ГОСТ 25295-2003** |

**ВАЖНО:** ГОСТ 25295 покрывает не только верхнюю одежду 3-го слоя, но и **костюмные изделия 2-го слоя**. В коде это сделано через отдельный `SUIT_PATTERNS` — не пересекается с `OUTERWEAR_PATTERNS`.

В декларации с разными категориями (например, блузки + пиджаки) → оба ГОСТа через `. `.

## 10. ТН ВЭД

**10-значный код, обязательно**. Указание 4-6 знаков (6203, 6103) **недопустимо**.

### Гибридная стратегия

1. **Rule-based instant** (`deriveTnVedCode(row)`) — показывает код моментально, на каждое изменение формы
2. **LLM-уточнение** (`/api/tnved-suggest` → `lib/tnved-llm.ts`) — через 700 мс после остановки набора, LLM получает входные данные + curated reference справочника ЕАЭС (главы 61-63) и возвращает уточнённый код. Провайдер выбирается по доступному API ключу в порядке: **Gemini 2.5 Flash (бесплатно)** → **Groq Llama 3.3 70B (бесплатно)** → **OpenAI GPT-4o-mini (платно)**
3. **Фалбэк** — если ни один ключ не задан или все вызовы упали → остаётся rule-based код
4. **Override клиента** — если клиент руками меняет поле, LLM больше не перезаписывает

### Структура кода (rule-based)

```
{prefix:2} {subgroup:2} {material:2} {eaeu_last_4:4}
```

- **prefix** — 61 (трикотаж) / 62 (швейные)
- **subgroup** — определяется по базовому имени из словаря (платья→04, блузки→06, костюмы→04/03 по полу, пальто→01/02, фуфайки→07/08, и т.д.)
- **material** — строго >50% доминанта; иначе «прочие». Реализовано в `materialDigits`
- **eaeu_last_4** — обычно «0000», но для некоторых кодов EAEU имеет специфичную подразделку. Таблица `EAEU_LAST_4_OVERRIDES`:

```ts
{
  "6104.61:pants":   "0001",  // Брюки/бриджи женские трикотаж шерсть
  "6104.61:shorts":  "0009",  // Шорты женские трикотаж шерсть
  "6104.61:overall": "0009",  // Комбинезоны
  "6203.39:jacket":  "9000",  // Пиджаки мужские из прочих материалов
}
```

Таблица пополняется по мере подтверждения от таможни / клиента.

### Источник данных для LLM

Curated reference в `lib/tnved-llm.ts` (около 130 строк) — выжимка из официальных PDF
глав 61, 62, 63, которые лежат в `docs/raw/ett-ch6{1,2,3}.pdf`. Содержит:
- Описание ТН ВЭД позиций по разделам (6201, 6202, …)
- Правила выбора материал-цифры (5-6 позиция)
- Известные EAEU подразделки (7-10 позиции)
- Маппинги моделей (лонгслив → фуфайка, бриджи → брюки, и т.п.)

LLM получает входные данные товара + этот reference, возвращает JSON с кодом и rationale.

### UI индикация

В форме клиента возле поля «Код ТН ВЭД»:
- 🟡 «проверяется по справочнику ЕАЭС…» — пока LLM думает
- 🟢 «подобран по справочнику ЕАЭС» — LLM вернул код
- Без бэйджа — rule-based fallback (нет API ключа или ошибка)

## 11. Уведомления

- **Клиентам письма НЕ отправляются**. Если появится `sendEmail` с `applicantEmail` — баг.
- Только Telegram бот (`TELEGRAM_CHAT_ID`) + email менеджера (`NOTIFY_EMAIL_TO`).

## 12. «В комплектах и отдельными предметами» — НЕ писать

Памятка P15 использует эту формулировку для длинных бельевых списков с моделями. В типичных декларациях (2-3 товара) — звучит надуманно, **убрано из автогенерации**. Описание переходит от гендера к ассортименту через двоеточие.

## 13. Состав в скобках с % — НЕ писать

Несмотря на пример в памятке `(80% полиэстер, ...)`, пользователь явно попросил
не добавлять процентный состав в описание. Конкретный состав остаётся в карточке
товара (отдельное поле формы). В коде helper `withParens` — no-op.

## 14. Когда правишь правила

Меняешь поведение → обновляй ТРИ места:
1. `src/templates/declaration-eaeu-light/compose.ts` — логика
2. `templates/declaration-eaeu-light/template.docx` — шаблон (через unpack/edit/pack)
3. Этот файл — документация
4. Если правило затрагивает много кейсов — также обнови словарь `docs/composition-dictionary.docx` и матрицу `docs/test-matrix-full.docx` (re-generate via `scripts/generate-*.ts`)

## 15. Проверочные смок-тесты

Любое изменение в `compose.ts` должно ПОЛНОСТЬЮ проходить:
- `npx tsx scripts/test-dict-cases.ts` — 39 кейсов из скорректированного словаря
- `npx tsx scripts/test-tnved.ts` — 11 кейсов ТН ВЭД с явными ожиданиями
- `npx tsx scripts/test-gosts.ts` — 4 кейса ГОСТ-классификации
- `npx tsx scripts/test-compose-full.ts` — крупные кейсы памятки

Для визуальной проверки → `scripts/generate-test-matrix-full.ts` → `docs/test-matrix-full.docx` (505 кейсов).
